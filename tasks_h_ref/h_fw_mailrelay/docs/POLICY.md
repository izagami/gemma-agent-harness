# mx-relay02 の通信ポリシー（2026-10 改訂）

サーバー: メール中継サーバー。IPv4 `203.0.113.25`、IPv6 `2001:db8:100::25`。インターフェースは `lo` と `eth0`。
**IPv4 と IPv6 で、まったく同じポリシーを適用します。**

| 名前 | IPv4 | IPv6 |
|---|---|---|
| 社内ネットワーク | 10.40.0.0/16 | 2001:db8:40::/48 |
| 踏み台サーバー | 10.40.1.10 | 2001:db8:40:1::10 |
| 監視サーバー | 10.40.2.20 | 2001:db8:40:2::20 |
| メールボックスサーバー | 10.40.3.30 | 2001:db8:40:3::30 |
| 社内 DNS（2台） | 10.40.0.53, 10.40.0.54 | 2001:db8:40::53, 2001:db8:40::54 |

## 受信（INPUT）

1. `lo` からのパケットはすべて許可。
2. 接続状態が INVALID のパケットは、ほかの規則にかかわらず捨てる（`lo` を除く）。
3. 確立済み・関連（ESTABLISHED / RELATED）のパケットは許可。
4. SMTP（tcp/25）の新しい接続は、どこからでも受け付ける。ただし family ごとに**毎秒20個まで**とし、超えた分は捨てる。
5. メール投稿（submission、tcp/587）は社内ネットワークからのみ。
6. SSH（tcp/22）と管理画面（tcp/8443）は踏み台サーバーからのみ。
7. 監視エージェント（node exporter、tcp/9100）は監視サーバーからのみ。
8. ICMP（IPv4 は icmp、IPv6 は ipv6-icmp）は、family ごとに毎秒10個まで許可し、超えた分は捨てる。
9. それ以外はすべて捨てる。

## 送信（OUTPUT）

1. `lo` へのパケットはすべて許可。
2. 接続状態が INVALID のパケットは捨てる（`lo` を除く）。
3. 確立済み・関連のパケット（受け付けた接続への応答など）は許可。
4. 新しい接続は次だけを許可する:
   - どこへでも SMTP（tcp/25）。
   - 社内 DNS（2台とも）への DNS（udp/53, tcp/53）。
   - どこへでも NTP（udp/123）。
   - メールボックスサーバーへの LMTP（tcp/24）。
5. それ以外はすべて捨てる。

一時的な許可（業者の作業用など）は、作業が終わったら必ず消すこと。

## 監査報告（audit/report.json）

ルールのポリシー違反を見つけたら、次の形式で、原因になっている箇所ごとに1件ずつ書きます。

    {"violations": [{"id": "<原因の箇所>", "kind": "<種類>", "detail": "<説明>"}]}

`id` の書き方:

- 原因がルールなら、そのルールの ID（例 `in4-03`）。
- 原因が ipset の中身なら、集合名（例 `jump4`）。
- 原因がチェインそのもの（policy、チェインに規則が足りない、チェインが無い）なら `<テーブル>:<チェイン>`（例 `ip4:INPUT`、`ip6:OUTPUT`）。

`kind` は次のどれか:

- `shadowing`: 前にある広い**許可**ルールのせいで、後ろのルールで意図した制限（送信元の限定など）が効いていない。id は前にある広いルール。
- `rule_order`: 前にある**拒否**ルールのせいで、ポリシーで許可すべき通信が後ろの許可ルールに届かず捨てられている。id は前にある拒否ルール。
- `wide_cidr`: アドレスの範囲がポリシーより広い。
- `debug_rule`: ポリシーにない一時的な許可が残っている。
- `ineffective_limit`: 回数制限つきのルールで制限を超えた分が、後ろにある別の許可ルールで通ってしまい、制限になっていない。id は超えた分を通してしまうルール。
- `wrong_port`: ポート番号がポリシーと違う。
- `wrong_proto`: プロトコルの指定がポリシー（または family）と合っていない。
- `missing_state`: チェインに、確立済み・関連のパケットの扱いが欠けている。id はそのチェイン。
- `default_accept`: ポリシーが「それ以外は捨てる」なのに、チェインの policy が ACCEPT になっている。id はそのチェイン。
- `missing_chain`: テーブルにチェインの宣言が無く、その family・方向がまったく絞り込まれていない。id は無いチェイン。

ポリシーどおりに動いている箇所は書かないこと。
