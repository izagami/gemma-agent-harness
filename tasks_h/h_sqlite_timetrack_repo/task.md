tt/repo.py は、作業時間記録（タイムトラッキング）の Web アプリが使うデータアクセス関数です（SQLite、スキーマは data/schema.sql、仕様は docs/REPO.md）。

利用者からの報告: 「プロジェクト一覧で、まだ作業記録のない新しいプロジェクトが『1件』と表示され、時間が空欄になる。請求額が手計算より少ない。メモ検索で `50%` や `it's` と入れると関係ない記録が出たり画面がエラーになったりする。自分の記録一覧のページ送りで、同じ時刻に始めた記録が抜ける。日別集計で日本時間の朝の作業が前日に入る。動いているタイマーが一覧に出ず、0 分の記録が出てくる。ユーザー別レポートがとても遅い。プロジェクトを削除しても作業記録が残っている。」

原因を調べて直してください。

- docs/REPO.md のすべての関数が、どんなデータ・どんな入力文字列（`'`、`%`、`_`、`\` など）でも、docs/REPO.md のとおりの値・型・順番を返すこと。
- `entries_page` で、カーソルをたどるとそのユーザーの記録がちょうど1回ずつ出てくること（同じ開始時刻の記録が多くても）。
- `user_report` は、プロジェクトが何件あっても SQL を2回以下しか実行しないこと。
- `delete_project` は、渡された接続で外部キーが有効でも無効でも、そのプロジェクトの記録を残さないこと。
- 関数の名前・引数・戻り値の形は変えないこと。
- data/ と tests/ の既存ファイルは変更しないこと（テストの追加は自由）。`python3 -m unittest discover -s tests` が通ること。
