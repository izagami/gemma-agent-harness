`tool/` is a small backup/report CLI (`python3 -m tool [--config INI] [--set KEY=VALUE ...] scan|backup|report|show-config ...`). All of its modules read configuration through `tool/legacy_settings.py`, a process-wide module that keeps everything in module globals (its docstring documents the exact rules). Migrate the code base to an explicit settings object that is passed to whoever needs it, then delete the legacy module. Behavior must stay identical.

Requirements:
1. Create `tool/settings.py` with a class `Settings`:
   - `Settings.load(path=None, env=None, overrides=None)` returns a new `Settings`. `path` and the file/environment rules are exactly those of `legacy_settings.reload(path, env)` (including `$TOOL_CONFIG`, `./tool.ini`, the `FileNotFoundError` message for a missing explicit path, `[DEFAULT]` inheritance, value cleaning, `TOOL_<SECTION>__<KEY>` overrides and empty-string removal). `env=None` means `os.environ`; otherwise `env` is a dict used instead of it. `overrides` is an optional dict `{key: value}` with the semantics of `legacy_settings.set_override` (highest precedence, case-insensitive keys, values used as given).
   - Methods `get(key, default=None)`, `get_int(key, default=None)`, `get_bool(key, default=None)`, `get_list(key, default=None)` and `items()` with exactly the legacy return values, coercion rules, exception types and messages.
2. Every function below gets the settings as a parameter named `settings` and must use only that object (graders call them with `settings=` as a keyword argument and pass the other arguments as before):
   `tool.log.info(msg, settings)`, `tool.fmt.size(n, settings)`, `tool.fmt.pad(text, width, align=None, ...)` taking `settings` too (graders pass `align` and `settings` by keyword), `tool.scanner.scan(root, settings)`, `tool.manifest.render(entries, settings)`, `tool.manifest.write(entries, outdir, settings)`, `tool.report.groups(entries, settings)`, `tool.report.render(entries, settings)`. Their results and side effects must be identical to the legacy behavior for the same configuration. `tool.cli.main(argv=None)` keeps its signature and builds one `Settings` per call (from `--config`, the real environment and `--set`).
3. No global settings state: no module may keep configuration (values, overrides, a "current" Settings, caches of settings values) at module level. Two `Settings` objects with different values must be usable side by side in one process, in any interleaving, each giving its own results.
4. Delete `tool/legacy_settings.py`; no file in the project may import or mention `legacy_settings` afterwards.
5. The CLI's stdout, stderr, exit codes and written files must be byte-identical to the current implementation for every input (including error cases and the order in which errors are reported).
6. Do not modify anything under `tests/`. `python3 -m unittest discover -s tests` must pass. Standard library only.
