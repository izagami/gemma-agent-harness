# vsort のバージョン規則（Semantic Versioning 2.0.0）

形式: `MAJOR.MINOR.PATCH[-PRERELEASE][+BUILD]`。先頭の `v`/`V` は付いていてもよい（無視する）。

- MAJOR, MINOR, PATCH は 10 進の整数。`0` 以外で先頭に `0` が付くもの（`01`）は不正。
- PRERELEASE は `-` の後ろの、`.` 区切りの識別子の並び。識別子は `[0-9A-Za-z-]` の 1 文字以上。
  数字だけの識別子は先頭に `0` を付けてはいけない（`rc.01` は不正、`rc.0` は正しい）。
- BUILD は `+` の後ろの、`.` 区切りの識別子の並び（`[0-9A-Za-z-]` の 1 文字以上、先頭 0 も可）。
  `+` より後ろは `-` を含んでいてもすべて BUILD（`1.0.0+exp.sha-5114f85` は PRERELEASE なし）。
- 空の識別子（`1.0.0-rc..1`, `1.0.0-`, `1.0.0+`）は不正。

## 優先順位（比較）

1. MAJOR, MINOR, PATCH を数値として順に比べる。
2. それらが同じなら、PRERELEASE のあるものは、ないものより小さい（`1.0.0-rc.1 < 1.0.0`）。
3. どちらも PRERELEASE があれば、識別子を左から1つずつ比べる:
   - 数字だけの識別子どうしは数値で比べる（`rc.2 < rc.10`）。
   - 英字等を含む識別子どうしは ASCII 順で比べる。
   - 数字だけの識別子は、英字等を含む識別子より常に小さい（`1.0.0-1 < 1.0.0-alpha`）。
   - すべて等しく一方が先に終わったら、識別子の少ない方が小さい（`alpha < alpha.1`）。
4. BUILD は優先順位に影響しない（`1.0.0+a` と `1.0.0+b` は等しい）。

例: `1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-alpha.beta < 1.0.0-beta < 1.0.0-beta.2 < 1.0.0-beta.11 < 1.0.0-rc.1 < 1.0.0`

## コマンド

- `python3 -m vsort sort [--desc] FILE` : 1 行 1 バージョン（空行と `#` 行は無視）を昇順（--desc なら降順）に、
  入力どおりの文字列で出力。優先順位が等しいものは入力の順を保つ（--desc でも同じ）。
- `python3 -m vsort max FILE` : いちばん大きいもの（等しいものが複数なら入力で最初のもの）。
- `python3 -m vsort cmp A B` : `<` `=` `>` のどれかを出力。
- 不正な行はそれぞれ標準エラーに `invalid version: <行>` と出し、残りで処理を続け、終了コード 1。
  不正な行がなければ終了コード 0。`cmp` で不正なら標準エラーに `error: ...`、終了コード 1。
